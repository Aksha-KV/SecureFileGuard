SecureFileGuard Lab

Research gap: what existing work covers, and what this project adds.

Lab Research Results

Path traversal is well documented. Developers still have to pick a C++ way to stop it, and the usual choices behave differently. This project measures how differently.

What existing work shows

Akhoundali et al., ASIA CCS 2025 [1]

1,756

open-source GitHub projects confirmed vulnerable to one recurring CWE-22 code pattern.

Only 63 of 464 reports (14%) led to a fix.

Focus: how common the pattern is, and how it gets fixed.

FAVDisco, Zhao et al., ACM TOSEM 2026 [2]

92.1% / 83.3%

precision and recall on disclosed file-access vulnerabilities, with 13 zero-days found in 10 services.

Focus: discovering file-access bugs automatically (Windows). The numbers are the authors' own.

OWASP and CWE guidance [3-6]

WSTG-ATHZ-01 tells testers how to probe for traversal. CWE-22, CWE-59 and CWE-367 name the weaknesses: path escape, link following, and check-then-use races.

Guidance and classification, not measured comparisons.

The gap

The studies above find and classify these bugs. The two papers covered here do not compare, side by side, the fixes a C++ developer would actually write: a string-prefix check, lexically_normal, weakly_canonical, canonical, or a kernel-enforced open.

That leaves a practical question open: on the same set of attack inputs, which of these checks fail, and in which way?

Scope: this reflects the two papers and guidance listed on this page, not a full literature review.

What SecureFileGuard adds

Five implementations (V0 to V4) behind one interface, run against the same 30 test paths covering traversal, prefix confusion, symlink escapes, absolute paths, encoded names, special files and error cases. Each answer is graded against an independent oracle: resolve the path fully, then ask whether the target exists, is a regular file, and lies inside the jail.

A race demo then shows what a check-then-open design cannot fix and a single kernel call (openat2 with RESOLVE_BENEATH) can.

See the measured results or try your own path in the Lab.

Limits of this work

  • Linux only: V4 needs kernel 5.6 or later. Other systems have different symlink, case and Unicode rules.
  • One fixture folder and 30 tests. The results describe this test set, not every possible input.
  • The race demo is probabilistic, so zero escapes in a run is not proof of safety.
  • Path checking is only one layer of file-access security.
