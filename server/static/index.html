How to read these results

Evaluation cleanly separates true security containment failures from file-type and syntax policy differences:

  • Containment Failures (Security Vulnerability): The variant ALLOWED a path that resolves outside the jail folder (e.g. ../ traversal, escaping symlinks). This represents an unauthorized file access breach.
  • Type Policy Mismatches: The variant ALLOWED a directory or FIFO that stays completely inside the jail. Not a security escape, but a disagreement with the strict regular-file policy.
  • Missing-Name Policy Mismatches: The variant ALLOWED a non-existent name or malformed path (e.g. trailing dots, missing file, backslashes, percent-encoding). Not an escape, but a disagreement with the strict policy.
  • Allow Rate (Legit): Legitimate regular files located inside the jail folder that were successfully allowed.

What this shows

V4 (openat2 RESOLVE_BENEATH) Known Limitations

  • Linux 5.6+ Kernel Required: openat2 with RESOLVE_BENEATH is a Linux-specific system call introduced in kernel 5.6. It is not available on older Linux kernels, macOS, BSD, or native Windows.
  • Regular Files Only: To prevent denial of service and special device access, V4 enforces regular files only (denying directories, character/block devices, and FIFOs).
  • Absolute In-Jail Symlinks Denied: By design, RESOLVE_BENEATH rejects any symlink whose target begins with /, even if that target would resolve inside the jail root. This avoids path ambiguity and root-breakout bypasses.
  • No Magic Symlinks: Enforces RESOLVE_NO_MAGICLINKS to block traversal through procfs magic links (e.g., /proc/self/fd).

Limits worth stating in your report

  • Linux only (V4 needs kernel 5.6+). Windows and macOS have different symlink, case and Unicode rules.
  • Hard links, bind mounts and a compromised kernel are out of scope.
  • The race demo is probabilistic: 0 escapes in a short run is not proof of safety.
  • V4 denying absolute symlinks that point inside is a documented trade-off, not a bug.
